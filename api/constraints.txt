# EVERY Python package the API image installs, at an exact version — direct AND transitive.
#
# requirements.txt pins only what GeoDeploy imports; the ~70 packages those pull in used to float to
# whatever was newest on the day of the build. That is how kombu 5.7.0 (2026-11-03) reached every new
# image without the `packaging` module it imports, and crashed the worker. It is also how 33 other
# packages had silently moved since the last working image, four of them by a major version.
#
# Used as a CONSTRAINTS file (`pip install -r requirements.txt -c constraints.txt`): it decides the
# version of anything that gets installed, and installs nothing by itself. api/Dockerfile and CI
# both use it, so the tests run against exactly what ships.
#
# This set: a fresh install of requirements.txt on 2026-11-19, under which all 1,414 API tests pass,
# all 73 geodeploy modules import and all 15 Celery tasks register.
#
# TO UPGRADE a package: change requirements.txt (or the line here), then regenerate from a clean
# python:3.12-slim:  pip install -r requirements.txt -c constraints.txt && pip freeze
# Never delete this file to "get the latest" — that is the bug it exists to prevent.
